# Repository maintenance

This repository intentionally uses a flat single-module library layout. Moving
`vcsel_lib.py` into a package would change public imports, so that migration
should happen separately from research-script cleanup.

## Layout

- `vcsel_lib.py`: NumPy VCSEL simulation API.
- `archive/adjoint/`: ignored local holding area for retired adjoint code. Move
  this directory outside the repository when the archived code is no longer
  needed locally.
- `examples/`: research and analysis programs. Long-running and exploratory
  programs remain here because several still rely on their current working
  directory.
- `scripts/`: CI helpers and batch-scheduler launchers.
- `rl/`: reinforcement-learning coupling designers and inspection tools.
- `rl/artifacts/`: ignored checkpoints, plots, and saved arrays generated by
  the RL tools.
- `tests/`: automated regression tests.
- `docs/`: repository policy and maintenance notes.
- `results/`, `output/`, and `tmp/`: generated local artifacts; these are
  ignored.

Run RL programs from the repository root with `python -m rl.<module>`. Their
paths are anchored to `rl/artifacts/`, so checkpoints and results do not depend
on the process working directory.

## Before merging

Run:

```bash
./scripts/run_checks.sh
git status --short
git diff --check
```

Review every untracked Python file explicitly. Generated arrays, figures,
movies, model checkpoints, and scheduler output should not be committed to the
source repository. Store research datasets and trained models in an artifact
store or a versioned release when they must be shared.

## Cleanup tiers

The following are reproducible caches or build products and are normally safe
to remove after closing Python processes:

- `__pycache__/`, `.pytest_cache/`, `.ruff_cache/`
- `build/`, `dist/`, `vcsel_lib.egg-info/`
- `.DS_Store`
- frame-only scratch output under `tmp/`

The following may contain unique research work and require inspection or a
backup before removal:

- top-level `results/` and category-local `examples/*/results/`
- category-local `examples/*/data/` and `examples/archive/`
- `rl/artifacts/`
- `working_model_backup/`

Use `git clean -ndX` for a dry-run view of ignored files. Do not run the same
command with `-f` until the research-data paths above have been backed up or
deliberately excluded from the cleanup.

## Packaging

`pyproject.toml` is the single source of package metadata. `setup.py` is only a
compatibility shim. Add a module to `tool.setuptools.py-modules` only when its
source file is present and intended to be part of the installed public API.
